💬 Messaging

Covers message sending, retrieval, filtering, search, and delivery status tracking.

Overview

The messaging module is the core runtime path for outbound and inbound communication. It supports text, media, and template payloads, stores canonical message records, and exposes query endpoints for operational visibility.

Primary Endpoints

  • POST /api/v1/messages — send text, media, or template messages
  • GET /api/v1/messages/:id — retrieve a single message
  • GET /api/v1/messages — list messages with pagination and filters
  • GET /api/v1/messages/search — full-text style message content search

Payload Model

  • Required: recipient (to), message_type
  • Text: content
  • Media: media_url plus optional content caption/title
  • Template: template_name, template_language, template_params

Status Lifecycle

Messages progress through sent → delivered → read, or terminate in failed. Status updates are typically propagated by webhook events and merged into existing message rows by WhatsApp message ID.

Validation Rules

  • Phone numbers must follow E.164 format (+{country}{number})
  • Outbound payload shape depends on message_type
  • Template messages require an approved template in WhatsApp Manager
  • Rate limits apply per API key

Dev Notes

  • Persist both internal ID and whatsapp_message_id for reconciliation
  • Prefer async retry for transient WhatsApp API failures
  • Add idempotency guard for duplicate send attempts from clients
  • Keep transport errors and provider errors separately observable

Example Request

curl -X POST http://localhost:8080/api/v1/messages \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "to": "+1234567890",
    "message_type": "text",
    "content": "Hello from the platform"
  }'
